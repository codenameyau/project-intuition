# Plan

Read `docs/00-vision.md` first: one sentence, what it does, the critical path with gates, kill criteria, and open decisions. This file holds the detailed phases per track.

Product name: **Dear You**. Three tracks. Track A is the explanation framework, Track B the predictive model, Track C the product that uses both.

Track A goal: a framework that takes any situation (a purchase, a snack, a crush, a grudge, a "gut feeling", an unexplained action) and returns a mechanistic, confidence-ranked, evidence-tagged, falsifiable explanation grounded in what is actually known about brains.

## Phase 0 — Literature sweep and framework v0.1 (done, 2026-11-08)

- Three research sweeps: connectomics and cellular maps; neuroscience and psychology of intuition; the five target domains.
- Delivered: thesis, biological substrate, seven-layer Intuition Stack, seven-question protocol, domain playbooks, five worked examples, annotated bibliography with evidence tiers, caveats, YAML spec, prompt template.
- Known gaps are listed at the end of `docs/06-evidence-and-sources.md`.

## Phase 1 — Harden the evidence base (1–2 weeks)

1. Read primary papers for every entry marked *(secondary)* and every tier-B entry whose number is quoted (Knutson, Plassmann, Montoya, Bornstein, Willis & Todorov). Correct numbers in place.
2. Fill the listed gaps: reciprocity of liking (Montoya & Insko 2008), mere-exposure imaging, Westgate percentages, anchoring/scarcity/social-proof neural reviews, sharp-wave-ripple primaries, food-advertising cue reactivity, default-mode role in mentalizing.
3. Add the two literatures the sweep did not reach: **individual differences** (disgust sensitivity, reward sensitivity, interoceptive accuracy scales) and **culture** (display rules, status signals, food norms) so the framework can take person- and culture-specific parameters.
4. Re-grade every tier after reading. Promote or demote with a one-line justification in the bibliography.

Done when: no entry in the bibliography rests on a press release or flashcard site, and every number in the docs cites the paper it came from.

## Phase 2 — Case library and rubric (2–3 weeks)

1. Collect 50+ real situations across the five domains (buying, eating, liking, feeling descriptions, "why did they do that"). Sources: own observations, public interviews, product reviews with stated reasons, Reddit "AITA"/"explain my behavior" threads (anonymized), choice-blindness and dumbfounding transcripts from the literature.
2. Run the protocol on each; store as `examples/<domain>/<slug>.md` with the output block.
3. Write a scoring rubric for an explanation: layer coverage, use of situational before dispositional drivers, evidence tagging present and correct, at least one testable prediction, narrative gap identified, ethical framing.
4. Blind-score a sample twice (two runs, or two people) to measure consistency of the protocol itself.

Done when: the library covers every driver in `framework/intuition-stack.yaml` at least twice, and inter-run agreement on the rubric is reported.

## Phase 3 — Validation against the literature's own tests (3–4 weeks)

The framework makes predictions. Check them against data that already exists.

1. **Stated reason vs. mechanism.** Use choice-blindness datasets (Johansson, Hall) and consumer-review corpora: does the protocol's reconstruction predict later behavior (re-purchase, return, repeat visit) better than the stated reason?
2. **Hunger and judgment.** Pre-registered designs exist on time-since-meal and parole, hiring, and shopping decisions. Does the L0 question recover the reported effects?
3. **Exposure and liking.** Compare framework predictions on proximity/exposure against classroom-seating and dorm-assignment studies.
4. **Price-expectation.** Plassmann-style effects: does the L2 "expectation" driver predict reported satisfaction better than product attributes?
5. Record each test as pass / partial / fail in `docs/08-validation.md`. A failed prediction changes the framework, not the write-up.

Done when: at least five framework predictions have been checked against independent data, with outcomes recorded.

## Phase 4 — Tooling (parallel with Phase 3)

1. `intuit explain "<situation>"` CLI: loads `framework/intuition-stack.yaml` and `framework/explain-protocol.md`, calls a model, returns the output block. Flags tier-C claims. Refuses requests for cue design against a target's interest.
2. `intuit feeling "<phrase>"`: the L5 decomposition only (valence, arousal, best-fit drive, context label, body-source candidates).
3. `intuit grade <example.md>`: applies the Phase 2 rubric.
4. Optional: a small knowledge graph (driver → evidence → paper → tier) generated from the YAML and bibliography so claims trace to sources automatically.

Done when: every worked example in `docs/05-worked-examples.md` can be regenerated by the CLI and scores ≥ the hand-written version on the rubric.

## Phase 5 — Ground in the connectome (ongoing, exploratory)

Added 2026-11-08: the census of mapped nervous systems and the lessons from each are in `docs/12-comparative-connectomes.md` (individuality without genetic difference; sex as connection-strength differences; stable decision core across development; evolution rewiring homologous neurons; drives as graded, persistent, separable, genetically indexed populations; recurrence and shortcuts; state modulation without a brain). Next schema revision adds per-drive time constants to the output schema.

1. Pull the FlyWire taste → proboscis circuit from codex.flywire.ai and reproduce a small leaky integrate-and-fire run (Shiu et al. methods are public). Purpose: a concrete, runnable demonstration that "intuition" at 10^5 neurons is wiring, for the docs and for intuition about what mammalian modulators add.
2. From MICrONS, extract the like-to-like connectivity statistics and write up how structural priors form.
3. Track the H01 follow-ups and any human connectomics releases; update `docs/02-biological-substrate.md` when something changes the picture.
4. Watch for arbitration-circuit papers (when does deliberation intervene); this is the framework's weakest mechanistic link.

# Track B — the predictive model (added 2026-11-08)

Goal: a model that, given a situation, a person profile, and a question, predicts what that person feels (quantified over 211 states plus VAD, drives, appraisals), what goes on in their mind, and what they will do, and answers binary, classification, or free-text questions with calibrated confidence. Full design: `docs/10-ml-training-plan.md`.

## B0 — Design (done, 2026-11-08)
- Quantitative emotion ontology, 211 states, four coordinate systems (`framework/emotion-ontology.csv`, `docs/08-emotion-ontology.md`).
- Person schema, 9 blocks, 60 evidence-tagged fields (`framework/person-schema.yaml`, `docs/09-person-model.md`).
- Output schema with decision heads and honesty fields (`framework/output-schema.json`, `examples/prediction-example.json`).
- Training plan, datasets, curriculum, evaluation, ethics (`docs/10-ml-training-plan.md`, `docs/11-ml-sources.md`).

## B1 — Ontology grounding (weeks 1–3)
- Biology block (added 2026-11-08, `docs/13-genomic-prediction.md`): polygenic scores as ancestry-flagged z-scores, large-effect preference variants (TAS2R38, ALDH2, CYP1A2, LCT, FTO, OR6A2, MC4R) as genotypes, CTRA as state. Apply for UK Biobank access as the only large human source with genotypes and affective items. Stretch: a genotyped replication of the Twin-2K-500 protocol.
- Replace prototype VAD with Warriner 2013 and NRC VAD values; store both raw sources per id.
- Fit appraisal columns from crowd-enVent and GRID; keep prototypes only where no data exists and mark them.
- Native-speaker review of the 15 culture-specific ids; add at least 20 more across 5 languages.
- Build and test the taxonomy mapping tables (Ekman, Plutchik, CK27, GoEmotions, OCC, GRID, ISEAR, EmpatheticDialogues → ontology ids).
Done when: every numeric column has a provenance field and no tier-C prototype is used where data exists.

## B2 — Data conversion and baseline (weeks 1–6, overlaps B1)
- Convert Stage A and B datasets to the (situation, profile, question → output) record format with masked missing fields and soft labels.
- 8B QLoRA baseline with LM loss on JSON, Number Token Loss on numerics, auxiliary heads on dense blocks.
- Match or beat EmoLLMs on GoEmotions, SemEval-2018, crowd-enVent appraisals; match COMET on ATOMIC xReact/oReact.

## B3 — Theory of mind and behavior (weeks 5–10)
- Add FANToM, OpenToM, BigToM, Hi-ToM, SOTOPIA; hold one benchmark out entirely.
- Reasoning-trace generation (seven questions, appraisal first) for Stage A+B; test whether traces improve intensity accuracy.

## B4 — Person conditioning (weeks 9–18)
- Integrate WASSA, PANDORA, Twin-2K-500, PRISM, Psych-101; OpinionQA and GlobalOpinionQA as audits only.
- Twin-2K-500 holdout: report individual-level accuracy normalized to its retest wave.
- Stereotype audit v1: within-group variance of predictions vs real within-group variance.

## B5 — Idiographic benchmark (weeks 12–30)
- Ethics review; consent protocol; Prolific recruitment.
- Pilot 200 participants: Park-style interview, 25 situations each across the five domains, tier-1 emotion ratings, VAD, free-text thoughts, choices (some with real stakes), retest wave for ceiling.
- Full collection 2,000 × 25. Release pseudonymized with the retest ceiling.
- Hard-negative generation and human direction-agreement checks for counterfactual sensitivity.

## B6 — Final model and release (weeks 26–34)
- 70B fine-tune on all stages; calibration; conformal sets; DPO on the text head only with numeric heads frozen.
- Model card: normalized accuracies, individual vs population numbers, stereotype audit, ToM scores, refusal policy, known limits.

## B-V — Veracity model (added 2026-11-08; design in `docs/20-veracity-model.md`)
- **B-V0** Design (done): evidence-ledger architecture, six channels with capped weak ones, interviewer, `veracity` output block, limits and refusals.
- **B-V1** Claim extraction and record-contradiction channel trained on synthetic contradictions built from person records; evaluation on constructed sets. Done when contradiction detection precision ≥ 0.95 at the default threshold.
- **B-V2** Verifiability counter and motive prior; conversational model on the Diplomacy corpus with UNIDECOR cross-corpus evaluation and DeFaBel-style artifact probes. Done when cross-domain AUC is reported and the linguistic channel's cap is set from it.
- **B-V3** Calibration and interviewer; false-accusation rate at every operating point; channel ablations published. Done when the model's stated expected-performance table in docs/20 is confirmed or corrected.
- **B-V4** Dear You integration as "consistency check" (C2 or later): ledger view, questions to resolve, reflection prompt on repeated queries, subject-visible counts. Owner go-ahead required.
- Rules: text and records only; never a verdict; refused for employment, education, legal, immigration, insurance, security, and minors; the false-accusation rate is the first number reported.

## Track B standing rules
- Genomics: masked outside the discovery ancestry; never inferred from ancestry, appearance, or name; no single-SNP personality claims.

- Report accuracy normalized to human test-retest, never raw.
- Report population-level and individual-level numbers separately; the output states which it is.
- Demographic fields are priors; idiographic fields carry the prediction. A model whose predictions collapse within a demographic group fails release.
- Soft labels in, distributions out. No majority-vote training on emotion data.
- Refuse manipulation design. Explain behavior; never optimize it against the subject.
- No profile built from scraped text about a named private individual.

# Track C — Dear You, the product (added 2026-11-08)

**Status rule (2026-11-08): documents only.** Track C stays at the specification stage until the owner says to build. No application code, no scaffolding, no infrastructure. The SQL and API files are design sketches, not deliverables.

Goal: a hosted app where a user keeps notes about people they know, gets a living person-schema profile with provenance, asks questions answered by the Intuition Stack and the Track B schema, and where the person can be invited to see, correct, and delete what is held. Full spec: `docs/15-product-spec.md`; data model: `product/schema.sql`; API: `product/api.md`.

## C0 — Spec (done, 2026-11-08)
## C1 — MVP (6 weeks): auth, Me profile, People, manual attributes, Notes, Ask via API model with the output schema, answer cards with drivers and coverage. Done when 20 users keep weekly notes and rate answers.
## C2 — Extraction (4 weeks): note → proposals → review; experiences; conflict surfacing; media as memories with scene captions; attribute history; the Person summary card (personality, aptitudes as bands, profession) with You said / They said / From note / Predicted badges and a Make predictions action (spec section 12). Done when ≥ 70% of proposals are accepted and the calibration dashboard is live.
## C3 — Consent and import (6 weeks): invites and subject portal; user-owned imports (Instagram, WhatsApp, Messenger exports filtered to the one thread with the Person; mail; calendar); one-item web clipper; extension "Save this conversation" for a thread open in the user's own account (spec section 13); public subject-rights form; legal review for EU/UK and California. Done when invited subjects have corrected profiles and the review has passed.
## C4 — Model (overlaps B4–B6): swap in the Track B model where it beats the API model on question evaluation; consented subject self-reports feed Stage E. Done when normalized accuracy is reported per question type.
## C5 — Mobile, reminders, shared profiles between two consenting users.

## Track C design rules
- Sources are the user's own notes, the user's own exports, the user's own conversation thread with the selected Person, and items clipped by hand with their URL.
- Sensitive fields (orientation, race, ethnicity, religion, politics, health) are entered by the user or the subject, encrypted, and kept out of model inputs by default.
- Media are memories with scene descriptions.
- No third-party sharing, no ads, no training on user data without explicit opt-in.
- Minors cannot be subjects beyond name, relationship, and dates.

# Track D — characters, NPCs, and model export (added 2026-11-08)

Goal: generate believable, consistent emotional life for fictional characters from the same model and schema, runnable inside games and on devices, and define how Track B models are exported as open and closed weights. Design: `docs/16-character-affect-engine.md`, `docs/17-model-export-and-deployment.md`. Documents only until told to build.

## D0 — Design (done, 2026-11-08): two-loop architecture, character sheet = person schema, expression mapping from ontology coordinates, authoring tools, evaluation; export tiers T0–T4 with formats, licensing, and consent rules; `drives_dynamics` added to the output schema.
## D1 — Tables and fast loop (after B2): publish T4 tables; reference fast-loop integrator with per-drive time constants; expression mapping demo in one engine. Done when two characters with different sheets visibly diverge on the same event.
## D2 — Distillation (after B4): T1 and T2 students from the teacher; GGUF and ONNX exports; T3 affect head. Done when each student keeps ≥ 90% of teacher scores per block and passes the stereotype audit.
## D3 — Authoring and evaluation (after D2): sheet editor, scenario tester, consistency linter; SOTOPIA-style believability and long-session consistency studies with players.
## D4 — Release: open weights for T2–T4 and dual-licensed T1 with the use policy; synthetic training corpus released alongside; model cards with per-tier latency on reference hardware.

## Track D rules
- Only Stage E records with the explicit release opt-in, and no Dear You user data, enter open-weight tiers; UK Biobank derivatives never leave the approved environment.
- Characters portraying real living people are out of scope.
- No character designed to pull the player's attachment system for engagement; the manipulation rule applies to players as to subjects.
- A model must refuse to load with a mismatched ontology or schema version.

# Critical path and gates (2026-11-08, from `docs/00-vision.md`)

1. Engine v0 (prompted frontier model + cohort engine + calibration layer), evaluated on Twin-2K-500 against its retest ceiling. Gate: positive skill over cohort baseline, binary calibration error < 0.05.
2. Dear You C1 on engine v0, 20 users. Gate: ≥ 50% weekly logging at week 8. Legal review for third-party data and consent flow starts here.
3. B1 and B2 in parallel (cheap).
4. Fine-tuned engine once C1 produces outcomes. Gate: beats engine v0 on the same holdouts.
5. Stage E sized to fill gaps in what Dear You has collected.
6. Track D after a distillable engine exists and a training-simulation partner is lined up.
7. Veracity last, as "consistency check" without a probability in v1; cross-domain evaluation and false-accusation rate published first.
8. Track E single-player world after D1 (it needs the distilled engine and the expression mapping); multiplayer only after the claimed-identity and consent-tier flows have passed legal review.

Kill criteria: no skill over cohort after two schema revisions → redesign inputs; within-group variance collapse → no release; users do not log outcomes → become an engine-licensing business; veracity false-accusation rate above the strong channel alone → cap or drop weak channels.

# Track E — the world and the consent-first network (added 2026-11-08; design in `docs/21-simulation-world.md`)

Goal: a 2D world where consented people from users' profiles live and interact under the engine, growing into a social network whose content is simulation rather than posts. Documents only until told to build.

## E0 — Design (done): architecture on the generative-agents pattern with the project's engine inside; relationship engine (`framework/relationship-schema.yaml`); what the science allows (friendship predictable with intervals, romance exploration-only); consent tiers; claimed-identity unification instead of shadow profiles.
## E1 — Single-player world (after D1): your self-profile plus sketch-tier characters; routines from habits and time-use base rates; conversation via T2; friendship dynamics; inspect panels. Done when two different profiles behave distinguishably and users can tell inner speech from stated speech.
## E2 — Relationship engine and scenarios: pair state, drivers, scenario runner with intervals; calibration against logged outcomes begins.
## E3 — Consented multiplayer: invites, claimed identity hub, consent tiers, perspective-separated profiles, visibility counts for subjects; legal review of the network model before launch.
## E4 — Network growth: shared worlds between consenting users; director tools; T2 on device for single-player.

## Track E rules
- No probabilistic matching of third parties across accounts. Identity unifies only when the person accepts invitations; sketches never cross accounts.
- Sketch-tier characters: no romantic, sexual, or humiliation scenarios; visible only to the writer; not playable.
- Romantic outcomes are explorations with the predictability ceiling shown; friendship and work dynamics are predictions with intervals.
- No photo likenesses as sprites. Minors: presence by name only.
- Subjects can see who simulated them and how often, at a category level.

## Posture (owner statement, 2026-11-08)

**Non-commercial.** Research, education, and fun. Every model, table, and document is released under CC BY-NC-SA-compatible research terms with the attribution file OCW requires. No pricing, no closed commercial tiers, no B2B licensing. Consequences: OpenStax and MIT OCW are usable for the project's own fine-tunes (`docs/23`, `docs/24`); Harvard free courses remain syllabus-only under edX terms; copyrighted textbooks remain design sources. Earlier mentions of pricing, commercial wedges, dual licensing, and closed API tiers in this file and the docs are superseded by this section.

## Standing rules

- **Evidence first.** Every driver has a tier. Tier C is never presented as settled. A failed replication demotes, immediately.
- **Situational before dispositional.** The protocol forces L0–L3 before trait talk; the tooling should enforce the order.
- **Hypotheses, not verdicts.** Output is about mechanisms, phrased with confidence levels, with alternatives shown.
- **No manipulation playbooks.** The framework explains; it does not design interventions against a subject's interest.
- **Dates are absolute.** Phase 0 completed 2026-11-08; later phases record completion dates in this file.

## Decisions taken in Phase 0

- Panksepp for drives, Barrett for feelings. They conflict philosophically; used here as complementary layers.
- Default-interventionist dual process as the control model, with uncertainty-based arbitration. Alternatives noted in caveats.
- Behavioral-economics "biases" (anchoring, scarcity, social proof) kept as drivers but tiered C until peer-reviewed neural reviews are found.
- Docs over code for v0.1. The YAML spec and prompt template are the only machine-facing artifacts; a CLI waits for Phase 4.
